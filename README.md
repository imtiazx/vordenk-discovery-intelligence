# Vordenk — Meta Global AI Developer Hackathon Kimi Project Pack

This pack configures Kimi as a **senior GenAI product engineer, architecture mentor, and patient pair-programming teacher** while you build a hackathon-ready slice of Vordenk. It is designed for a beginner in end-to-end product engineering who wants to understand and own the implementation rather than delegate the entire project to an AI coding agent.

## What Vordenk is

Vordenk's long-term vision is an **AI-native Enterprise Transformation Operating System**. It will ultimately support the full transformation lifecycle: engage, discover, diagnose, design, mobilise, deliver, and realise value.

The hackathon build is one focused but meaningful part of that platform: **Vordenk Discovery Intelligence**. It turns workshop conversations and supporting artifacts into a persistent, evidence-linked model of how a business works, what is unclear or broken, what questions should be asked next, and what should be validated. This is more than note-taking or a basic RAG chatbot.

## Set up the Kimi Project

1. Create a Kimi Project named **Vordenk — Meta Global AI Hackathon**.
2. Open `00_KIMI_PROJECT_INSTRUCTIONS.md` and paste the section under **Paste into Kimi Project Instructions** into the Project Instructions field.
3. Upload the other Markdown files to the Project. If file limits apply, start with `01`, `02`, `03`, `04`, `07`, `08`, `09`, `10`, `11`, and `15`.
4. Start a new chat and use **First chat: orient me, challenge the plan, and teach me** from `11_PROMPT_LIBRARY.md`.
5. Tell Kimi **not to write code in the first conversation**. First agree on the smallest buildable end-to-end slice and test access to Meta Model API.

## Important competition constraints

- The repository must be **public**.
- The demo must clearly show functionality built during the hackathon. Mark hackathon-created work and keep honest Git history.
- Meta models must be incorporated meaningfully. Do not build a generic RAG chatbot and add a Meta API call as decoration.
- The submission requires an accessible **three-minute demo video**.
- The deadline in the guide is November 4, 2026 at 9:00 PM Eastern Time, which converts to **November 5 at 7:30 AM India Standard Time**. Verify the official event page/portal for any updates and submit early.
- Winning is never guaranteed. The pack aims to maximise originality, a working end-to-end flow, meaningful Meta-model use, technical clarity, product polish, and a compelling demo.

## Source-of-truth policy

Kimi Project reference files are planning documents, not the code repository. Once the GitHub repository exists, the actual source code, tests, issues, and reviewed decision log become the source of truth. When a decision changes, ask Kimi to propose updates to the relevant Markdown file and review the changes before accepting them.

Use synthetic or public workshop data only. Do not use confidential Accenture, client, or employer data, meeting recordings, internal documents, or proprietary code unless you have explicit permission and the use is permitted by the applicable rules.
