# Three-Minute Demo and Submission Plan

## Demo goal

Show a judge the difference between an ordinary meeting summary and a **living, evidence-linked transformation blueprint**. Demonstrate real product behaviour and actual Meta-model use, not a slide deck full of future promises.

## Suggested 3-minute sequence

### 0:00–0:20 — The problem

“As an AI consultant, I need to listen, understand complex processes, ask useful questions, and document decisions simultaneously. Notes alone don't preserve a validated model of how the business works. Vordenk turns discovery evidence into a living transformation blueprint.”

### 0:20–0:45 — Start a synthetic engagement

Show the engineering-change use case and ingest the first synthetic workshop transcript. If audio transcription is working, demonstrate a short clip transcribed by Muse Voice Transcribe; otherwise do not pretend transcript paste is live audio.

### 0:45–1:20 — Show meaningful Meta reasoning

Show actual Muse Spark-powered extraction of process steps, actors/systems, pain points, assumptions, and source references. Point to the model call/role clearly. Do not show API keys. Display the user's evidence status rather than a wall of JSON.

### 1:20–1:50 — Show the discovery intelligence

Reveal the rendered process map and 2–3 prioritised questions tied to a real gap. Show a contradiction or unresolved assumption and why it matters. Make clear this is more than summarisation.

### 1:50–2:25 — Prove memory and human control

Load the second session with a seeded contradiction. Show both pieces of evidence; validate or correct the appropriate item; reload or run the next synthesis to prove the correction persists. This is the key technical/product moment.

### 2:25–2:45 — Show evidence and evaluation

Open one material claim and point to its source. Show actual evaluation results for the small test set, including limitations, or show the checks the app performs if evaluation is still limited. Do not invent benchmark numbers.

### 2:45–3:00 — Close with the full vision

“Discovery Intelligence is Vordenk's first capability. The same Transformation Memory is designed to carry validated understanding into diagnosis, TO-BE design, requirements, implementation, and measured business outcomes.”

## Submission checklist

- [ ] Correct track matches the application.
- [ ] Public GitHub repository is accessible without login.
- [ ] README includes problem, solution, architecture, setup, environment variables, model roles, limitations, and screenshots/demo.
- [ ] Public code has no API secrets, tokens, private client data, or copyrighted assets without rights.
- [ ] `HACKATHON_BUILD_LOG.md` records what was created during Oct 27–Nov 4.
- [ ] Git history and demo make newly built functionality clear and truthful.
- [ ] Meta model(s) actually run in the main workflow and are described accurately.
- [ ] Three-minute demo link is accessible to judges.
- [ ] Final demo only claims features that actually work.
- [ ] Known limitations and future roadmap are clearly distinguished from implemented features.
- [ ] The final form is submitted before the official deadline; retain confirmation.
